Manual Testing

Foundations every tester needs before touching a framework.

Key Concepts

  • SDLC vs STLC — where testing fits in the software lifecycle
  • Test case design: equivalence partitioning, boundary value analysis, decision tables
  • Levels of testing — Unit, Integration, System, Acceptance
  • Types — Functional, Regression, Smoke, Sanity, Exploratory, UAT
  • Severity vs Priority in bug reports
  • Writing a clear bug report: steps, expected, actual, evidence
  • Test plan vs test strategy vs test case
  • Traceability matrix — mapping requirements to test cases

Bug Report Template

Title: Login button unresponsive on Safari 17
Environment: macOS 14, Safari 17.4
Steps to Reproduce:
 1. Open login page
 2. Enter valid credentials
 3. Click "Login"
Expected: User redirected to dashboard
Actual: Button click has no effect, no console error
Severity: High   Priority: P1
Attachments: screen-recording.mp4

Automation Testing

Turning repeatable manual checks into scripted, reliable regression suites.

Why Automate

  • Repeated regression runs, faster feedback in CI/CD
  • Consistent execution — removes human error on repetitive steps
  • Good candidates: stable, repetitive, data-driven, high-risk flows
  • Bad candidates: one-off tests, UI still changing daily, exploratory checks
  • Framework layers: driver/config, page objects, test data, reporting
  • Automation pyramid: many unit tests, fewer API tests, fewest UI tests

Sample Page Object (Selenium + Java)

public class LoginPage {
  WebDriver driver;
  By username = By.id("username");
  By password = By.id("password");
  By loginBtn = By.cssSelector("button[type=submit]");

  public LoginPage(WebDriver driver) { this.driver = driver; }

  public void login(String user, String pass) {
    driver.findElement(username).sendKeys(user);
    driver.findElement(password).sendKeys(pass);
    driver.findElement(loginBtn).click();
  }
}

Selenium

Cross-browser WebDriver automation for web applications.

Key Concepts

  • WebDriver architecture & browser drivers
  • Locators: id, name, css, xpath — priority order
  • Waits: implicit, explicit (WebDriverWait), fluent wait
  • Actions class for hover, drag-drop, keyboard events
  • Handling alerts, frames, multiple windows
  • TestNG / JUnit integration & parallel execution

Explicit Wait Example

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement el = wait.until(
    ExpectedConditions.elementToBeClickable(By.id("submit"))
);
el.click();

Playwright

Modern, fast, auto-waiting browser automation from Microsoft.

Key Concepts

  • Auto-waiting — no manual sleeps needed
  • Locators: get_by_role, get_by_text, get_by_test_id
  • Built-in test runner with parallel workers
  • Trace viewer for debugging failed runs
  • Multi-browser: Chromium, Firefox, WebKit from one API
  • Network interception & API mocking

Sample Test

import { test, expect } from '@playwright/test';

test('login works', async ({ page }) => {
  await page.goto('https://example.com/login');
  await page.getByLabel('Username').fill('admin');
  await page.getByLabel('Password').fill('secret');
  await page.getByRole('button', { name: 'Login' }).click();
  await expect(page).toHaveURL(/dashboard/);
});

Cypress

Developer-friendly end-to-end testing that runs inside the browser.

Key Concepts

  • Runs directly in-browser — real-time reload & time travel debugging
  • Automatic retries on assertions
  • Custom commands for reusable steps
  • cy.intercept for network stubbing
  • No native multi-tab support (by design)

Sample Test

describe('login flow', () => {
  it('logs in successfully', () => {
    cy.visit('/login');
    cy.get('#username').type('admin');
    cy.get('#password').type('secret');
    cy.get('button[type=submit]').click();
    cy.url().should('include', '/dashboard');
  });
});

API Testing

Verifying services at the HTTP layer — faster and more stable than UI tests.

Key Concepts

  • HTTP methods: GET, POST, PUT, PATCH, DELETE
  • Status codes: 2xx success, 4xx client error, 5xx server error
  • Request/response validation — schema, headers, body
  • Authentication: API keys, Bearer tokens, OAuth2
  • Tools: Postman, RestAssured, Playwright API testing

RestAssured Example

given()
  .header("Content-Type", "application/json")
.when()
  .get("/api/users/1")
.then()
  .statusCode(200)
  .body("name", equalTo("Admin"));

SQL

Backend data validation — every QA engineer's second language.

Key Concepts

  • SELECT, WHERE, JOIN (inner/left/right), GROUP BY, HAVING
  • Primary key vs foreign key
  • Aggregate functions: COUNT, SUM, AVG, MAX, MIN
  • Subqueries vs joins
  • Using SQL to validate test data setup/teardown

Sample Query

SELECT u.id, u.name, COUNT(o.id) AS orders
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id, u.name
HAVING COUNT(o.id) > 0
ORDER BY orders DESC;

Jenkins

Automation server that triggers test suites on every build.

Key Concepts

  • Freestyle jobs vs Declarative pipelines
  • Jenkinsfile stored in source control
  • Triggers: SCM polling, webhooks, scheduled (cron)
  • Plugins for reporting (Allure, JUnit, HTML publisher)
  • Parameterized builds for cross-browser runs

Sample Jenkinsfile

pipeline {
  agent any
  stages {
    stage('Test') {
      steps { sh 'mvn test' }
    }
  }
  post {
    always { junit 'target/surefire-reports/*.xml' }
  }
}

CI/CD

Continuous Integration & Continuous Delivery — shipping with confidence.

Key Concepts

  • CI: merge code frequently, run automated tests on every push
  • CD: automatically prepare/deploy a release-ready build
  • Pipeline stages: build → test → package → deploy
  • Shift-left testing — catching bugs earlier in the pipeline
  • Tools: Jenkins, GitHub Actions, GitLab CI, CircleCI

GitHub Actions Snippet

name: Run Tests
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npx playwright test

Agile

The framework most QA teams plan and deliver within.

Key Concepts

  • Scrum roles: Product Owner, Scrum Master, Dev Team
  • Ceremonies: Sprint Planning, Daily Standup, Review, Retrospective
  • Artifacts: Product Backlog, Sprint Backlog, Increment
  • Story points & velocity for estimation
  • Definition of Done vs Definition of Ready

QA in a Sprint

  • Refine acceptance criteria during backlog grooming
  • Write test cases alongside development, not after
  • Automate regression as stories close
  • Report bugs directly against the sprint board

Jira

Tracking stories, bugs, and sprints in one board.

Key Concepts

  • Issue types: Epic, Story, Task, Bug, Sub-task
  • Workflow states: To Do → In Progress → In Review → Done
  • Linking test cases to stories for traceability
  • Filters & JQL for custom bug queries
  • Dashboards for sprint burndown & bug trends

Sample JQL

project = "QA" AND issuetype = Bug
AND status != Done
AND priority in (High, Highest)
ORDER BY created DESC
